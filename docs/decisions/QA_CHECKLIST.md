## ✍️ 체크 기록 규칙 (필수)

항목을 `[x]`로 체크할 땐 **반드시 근거를 옆에 남긴다.** 체크박스만 남기면 "왜 통과했는지" 추적이 안 돼 회귀 시 근거가 소실된다.

**인라인 형식** (항목 뒤에 ` — ` 붙여 기록):
```
[x] 항목 설명 — 🔧YYYY-MM-DD · `수정파일.swift` · 해결방법 요약 · ✅검증방법
```

| 마커 | 의미 | 남길 내용 |
|---|---|---|
| 🔧 | **코드 수정으로 해결** | 날짜 · 수정/신규 파일 경로 · 어떻게 고쳤는지 |
| ✅ | **런타임/실기기 QA 통과** | 날짜 · 검증 수단(시뮬/실기기·어떤 조작) |
| 👁️ | **코드 수정 없이 확인만** | 날짜 · 확인 방법(코드 리뷰/DB 조회 등) |

- 코드로 고쳤지만 아직 런타임 QA 전 → `[ ]` 유지 + 🔧 기록만 부착("구현됐으니 이걸 테스트하라"는 신호).
- 런타임까지 통과해야 `[x]`.

예)
```
[x] 예매처 2곳↑ 시트 노출 — 🔧2026-07-22 · `BookingProviderSheetViewController.swift` 신규 · requestBooking() 분기 · ✅2026-07-22 시뮬 3곳 이벤트에서 시트 확인
```

## A. 공통 상태 매트릭스

모든 데이터 로딩 화면은 아래 4상태를 갖는다.

| 상태 | 확인 포인트 |
|---|---|
| **로딩** | 스켈레톤 또는 인디케이터가 뜨는가? 데이터 도착 시 자연스럽게 사라지는가(페이드)? |
| **정상** | 실데이터가 올바르게 렌더되는가? 이미지 로드되는가? |
| **빈(empty)** | 0건일 때 빈 상태 안내가 뜨거나 섹션이 깔끔히 숨는가? (빈 카드/깨진 레이아웃 금지) |
| **에러** | 실패 시 안내(토스트/알럿)가 뜨는가? 재시도 수단이 있는가? |

**화면별 로딩/에러 표현 방식이 다르다 (일관성 QA 대상):**

| 화면 | 로딩 | 에러 표현 | 재시도 |
|---|---|---|---|
| Home NOW | HomeSkeletonView | 알럿 "다시 시도"/"닫기" | O |
| Home PLAY | MyModeSkeletonView | 알럿 | O |
| Artist | ArtistSkeletonView | 알럿 | O |
| **ArtistDetail** | ArtistDetailSkeletonView | **토스트(재시도 없음)** | **X** |
| **ConcertDetail** | ConcertDetailSkeletonView | **토스트(재시도 없음)** | **X** |
| Search 결과 | 인디케이터 | 인라인 빈뷰 문구 | 세그먼트 재선택만 |
| BookingList/Reviews/Inquiry | 인디케이터 | 알럿 | O |

> ⚠️ ConcertDetail/ArtistDetail은 에러 시 **빈 placeholder 카드**가 남고 토스트만 뜬다. 재시도 버튼 없음 → 뒤로 나갔다 재진입해야 함. QA 시 "에러 후 화면이 비어보이는지" 반드시 확인.

## D. 크로스컷 리스크

> 코드 스캔에서 발견된 **잠재 결함**. ✅는 코드 수정 완료(빌드 검증), 재현 QA만 남음. ⬜는 미착수(성격상 코드 수정 대상 아님).

**해결됨 (2026-07-21 세션):**

- ✅ **오프라인 포그라운드 복귀 시 강제 로그아웃** — PR #93
  `Error.isNetworkConnectionError`로 네트워크 오류를 세션 만료와 구분. `validateSession`/`freshToken` catch에서 네트워크 오류면 세션 보존. **재현 QA**: 로그인 → 기내모드 → 백그라운드 → 복귀 시 로그인 유지.
- ✅ **쓰기 경로가 401→로그아웃 로직 우회** — PR #101
  `SupabaseService.startAuthObserver()`가 `authStateChanges`의 `.signedOut`을 구독해 읽기·쓰기 어느 경로의 세션 만료든 중앙에서 `userDidLogout` 발행. **재현 QA**: 세션 만료 상태에서 팔로우/관심 토글 시 Guest 전환.
- ✅ **이미지 로드 실패 시 빈칸** — PR #95
  자동 재시도(2회, 세대 토큰 방어) + placeholder 파라미터. 시뮬레이터 런타임에서 히어로 포스터 로드 확인. **재현 QA**: 느린 망에서 재시도 채움, 빠른 스크롤 시 셀 이미지 안 섞임. (디스크 캐시·placeholder 색 전면 적용은 후속)
- ✅ **네트워크 상태 모니터 부재** — PR #99
  `NetworkMonitor`(NWPathMonitor) + `NetworkStatusBanner` 전역 배너. **재현 QA**: 기내모드 시 "인터넷 연결이 끊겼어요" / 복귀 시 해제.
- ✅ **Home/Artist 블록 observer 해제 미확인** — PR #97
  `notificationTokens` + deinit 해제로 통일(Artist도 함께). 정적 확인 완료.

**미착수 (코드 수정 대상 아님):**

- ⬜ **네트워크 에러 텔레메트리 누락**
  `ErrorReporter.capture(.network)` 호출처 없음. → **재평가: 의도된 설계로 판단.** 오프라인은 사용자 환경 문제(정상 상황)라 로그로 남기면 노이즈만 증가. `.http`/`.decoding`(서버·앱 문제)만 남기는 현재가 합리적. 수정 보류.
- ⬜ **크래시 리포트 best-effort**
  순수 Swift `fatalError`는 시그널 핸들러로만 잡혀 누락 가능(`ErrorReporter.swift:10`). → 크래시 SDK(Crashlytics 등) 도입 검토 영역.
- ⬜ **라이트 모드 강제**
  시스템이 다크여도 앱은 라이트 고정. → 기획 확인 필요(다크 지원 로드맵).
- ⬜ **작은 화면(SE) 레이아웃**
  예매하기 버튼 등 고정폭 요소가 320pt에서 오버플로우 안 나는지. → 실기기/SE 시뮬 QA.

## F. DB 데이터 품질 (Supabase 실데이터 점검)

> **UI QA만으론 못 잡는다.** 화면은 멀쩡해 보여도 DB 값이 잘못됐거나 결측이면 사용자에게 깨진 경험이 간다. 이번 세션(2026-07-21)에 이 섹션이 없어 `status='ongoing'` 미매핑 버그를 UI 스크린샷으로 "정상"이라 오판했다 → DB 조회로 발견.
>
> **점검 방법**: admin 레포 `.env.local`의 `SUPABASE_SERVICE_ROLE_KEY`로 REST 조회(service_role은 RLS 우회). 릴리스 전 / DB 스키마·enum 변경 시 실행.

### F0. 조회 스니펫 (재사용)

```bash
cd /Users/sjw/ted.urssu/Articket-admin
URL=$(grep NEXT_PUBLIC_SUPABASE_URL .env.local|cut -d= -f2|tr -d '" ')
KEY=$(grep SUPABASE_SERVICE_ROLE_KEY .env.local|cut -d= -f2|tr -d '" ')
# count 헬퍼 (Prefer: count=exact → content-range 헤더의 total)
cnt(){ curl -s "$URL/rest/v1/$1" -H "apikey: $KEY" -H "Authorization: Bearer $KEY" \
  -H "Prefer: count=exact" -I 2>/dev/null | grep -i content-range | sed 's/.*\///' | tr -d '\r'; }

cnt "events?select=id"                                    # 총 이벤트
cnt "events?select=id&status=is.null"                     # status NULL
cnt "events?select=id&status=not.in.(upcoming,on_sale,ongoing,ended)"  # 미지 status ★
cnt "events?select=id&booking_url=is.null"               # 예매링크 결측
cnt "events?select=id&status=eq.on_sale&booking_url=is.null"  # 예매중인데 링크없음(모순) ★
cnt "venues?select=id&address=eq."                       # 주소 빈값
# 미지 status 실제 값 확인:
curl -s "$URL/rest/v1/events?select=status,title&status=not.in.(upcoming,on_sale,ongoing,ended)&limit=20" \
  -H "apikey: $KEY" -H "Authorization: Bearer $KEY"
```

### F1. status 무결성 (★ enum 동기화 — 가장 중요)

- [ ] **미지 status 0건** — `not.in.(upcoming,on_sale,ongoing,ended)` = 0. **>0이면 admin이 새 enum 추가했는데 iOS 미반영** → `ConcertStatus`·`TicketSaleStatus`·`EventRow`·`SupabaseArtistRepository` 매핑 확인 (이번 세션 `ongoing` 14건이 이 케이스)
- [ ] status=NULL 0건 (init 스키마상 NOT NULL이라 정상 0)
- [ ] admin 정식 enum = `upcoming | on_sale | ongoing | ended` (migration `20260523000000_add_ongoing_status.sql`). iOS 매핑 4개 전부 존재 확인

### F2. booking_url / booking_links (예매 링크) — admin #16

- [ ] on_sale인데 booking_url NULL = 모순. 임계 0 지향(2026-07-21: 71건)
- [ ] iOS 방어 확인: 링크 없으면 예매하기 탭 시 안내 토스트 + `event_booking_link_issues` 기록(정상 동작). **근본 해결은 admin 백필**
- [ ] **`booking_links`(JSONB) 정제 정확성** (2026-07-22 신규 컬럼) — provider 키 매핑(interpark/yes24/melon/yanolja/klook)·표시순서(PROVIDERS 우선순위)·죽은 URL 제외. 2곳↑ 예매처 이벤트(admin 실측 62건)가 앱에서 시트로 뜨는지 교차 확인
- [ ] `booking_links` 항목 shape `{provider,label,url}` 완전성 — 셋 중 하나라도 결측이면 iOS가 해당 항목 드롭(`EventRow.toConcertDetail`). 결측 다발 시 admin 정제 로직 점검
- 기준선(2026-07-21): 전체 booking_url NULL 735/1449(51%), on_sale+NULL 71, `event_booking_link_issues` 13
