# Articket-iOS 개발 워크플로우

모든 개발 요청에 대해 아래 순서를 반드시 따르세요.

## Phase 1 — 플랜 보고 (먼저 출력)
요청을 분석하고 한국어로 다음을 보고:
- 무엇을 변경할지 (1~3줄 요약)
- **왜 그 방법인지** (대안 대비 선택 근거, 설계 의도)
- 수정 예상 파일 목록 (CODEMAPS 기반으로 경로 예측)

## Phase 2 — 파일 탐색 (최소화)
1. `docs/CODEMAPS/[FEATURE].md` 먼저 읽기
2. 네이밍 규칙으로 경로 예측 → 타깃 파일 직접 열기
3. Glob/Grep은 CODEMAPS에 없는 파일만 사용

## Phase 3 — 코드 수정
- 타깃 파일만 열어서 필요한 부분만 Edit
- 기존 패턴(PATTERNS.md)과 일치하게 작성

## Phase 4 — 검증
- 수정 내용이 기존 패턴(ViewModel/Cell/UseCase)과 일치하는지 확인
- 가능하면 xcodebuild로 빌드 확인

## Phase 4.5 — docs/CODEMAPS 업데이트
코드 변경 후 반드시 아래 문서를 최신 상태로 갱신:
- 새 파일/클래스 추가 시 → 해당 `docs/CODEMAPS/[FEATURE].md` 업데이트 (없으면 신규 생성)
- 아키텍처/패턴 변경 시 → `docs/CODEMAPS/PATTERNS.md` 업데이트
- DI 연결·네비게이션 구조 변경 시 → `CLAUDE.md` 아키텍처 섹션 업데이트
- 갱신 대상이 없으면 생략 가능 (단순 버그픽스 등)

## Phase 5 — 상세 보고 (완료 후 출력)
다음 형식으로 반드시 보고:

```
### 수정 완료 보고

**변경 파일**
- `경로/파일명.swift` — 변경 내용 한 줄 요약

**변경 상세 및 선택 이유**
각 파일에서 무엇을 왜 변경했는지 (이 방식을 선택한 근거 포함)

**검증**
검증 방법 및 결과
```

완료 후 `/ship` 입력 시 한국어 커밋/이슈/PR을 생성합니다.
